## 2. Bug 列表

### BUG-001 · S2 · 远征中可以无限重打每日挑战，金币和卡牌都算进这一局
- **Severity**：S2-High · **Priority**：P1-Fix this sprint · **Category**：Gameplay / Economy · **Frequency**：Always · **Regression**：No（远征版新出现的）
- **系统**：每日挑战 × 远征经济
- **复现**
  1. 开始一次远征，打到第 5 轮（`M.round >= DAILY_MIN_ROUND`）。
  2. 结算页 →「目标」→「每日」→「📅 开始每日挑战」，打完后点「📅 再来一次」，重复几次。
- **预期**：设计文档写的是"每日挑战暂时保留单轮玩法，**从营地进入**"。远征中不应该能进入；就算能进，也不应该把金币、卡牌带进这一局。
- **实际**（`t8_dailyrun.cjs`，种子 81）：每打一次，金币和卡牌都直接进这一局，不掉心，地图也不前进：

  | | 金币 | 卡牌总数 | 心 | `M.round` |
  |---|---|---|---|---|
  | 进入前 | 750 | 104 | 3 | 5 |
  | 每日 ×1 | 32,686 | 477 | 3 | 6 |
  | 每日 ×2 | 42,543 | 722 | 3 | 7 |
  | 每日 ×3 | 51,221 | 952 | 3 | 8 |

  第一次打还因为成就拿了 +13 金魂。`M.round` 也跟着涨，会污染结算页的"轮数"和排行榜「最远远征」的同分比较（`best.depthRounds`）。
- **代码位置**：`index.html:2103`，`tSubs` 只要 `M.round>=DAILY_MIN_ROUND` 就显示 `daily` 子页，没有排除 `M.run`；`renderDaily`（1178）、`dailyAgain`（2879）里调用 `startRound(false,{daily:1})`；`earn()` / `giveCard()` 都没有区分 `DAILY`，直接加到 `M.money` / `M.owned`；`startRound` 里的 `M.round++` 也没有区分。
- **建议**：`M.run` 存在时隐藏「每日」子页（或者改成"回营地后可挑战"的提示）；如果保留，每日这一轮的金币和卡牌不要进局内，也不要增加 `M.round`。

### BUG-003 · S3 · 刷新页面可以免费重抽秘符和开局招募（绕过付费重抽）
- **Severity**：S3 · **Priority**：P2 · **Category**：Gameplay / Exploit · **Frequency**：Always
- **复现**：弹出秘符三选一（或开局招募三选一）时刷新页面，回来后选项变了。
- **预期**：同一次奖励在刷新前后选项一样（秘符本来有"🎲 重抽（花金币）"按钮）。
- **实际**（`t4_reload.cjs` e）：同一个 `sigQ` 刷新前是「炽心, 宽囊, 涌泉」，刷新后变成「涌泉, 护身符, 锐眼」。招募弹窗刷新后卡也换了一批。真实浏览器里随机数不固定，所以品级（白银 / 黄金 / 棱彩）也会重新抽。
- **代码位置**：`offerSigil`（2314-2318）在显示时才调用 `rollTier` / `sigilPicks`，结果没有存档，只存了 `sigQ` 的来源；招募的 `openPick`→`rollPick`（1541-1544）也一样。
- **建议**：抽出来的品级和选项写进 `M.sigQ[0]` / `M.recruitPicks` 再显示。

### BUG-004 · S3 · 在营火、黑市、奇遇页面刷新，这一站被消耗了，但效果没有生效
- **Severity**：S3 · **Priority**：P2 · **Category**：Gameplay · **Frequency**：Always

### BUG-007 · S3 · 营地（不在远征中）进不去「设置」：不能导出 / 导入存档码，也不能改统计开关或重置
- **Severity**：S3 · **Priority**：P2 · **Category**：UI / Save · **Frequency**：Always
- **复现**：打完一局回到营地，或者新玩家刚到营地，找存档码导出 / 导入。
- **预期**：设计说"设置……永久保留"。存档只在本地，最需要备份的时候恰恰是局与局之间（金魂、传承、解锁都在这时）。

### BUG-008 · S4 · 回到营地后，顶部 HUD 和侧栏还显示上一局的金币和卡组
- **Severity**：S4-Low · **Priority**：P3 · **Category**：UI · **Frequency**：Always
- **实际**：营地顶部显示"✦ 余额 217""余额 2.70万"等上一局（或营地里打完每日挑战）的余额（截图 `shots/t1_zh_9_camp2.png`，`t4` h：`hud: "✦ 余额 2.70万"`）。`M.money / M.deck / M.relics / M.sigils` 一直保留到下次 `startRun` 才清。不影响数值（`startRun` 会重置），但容易让人以为金币会带进下一局。
- **代码位置**：`toCamp` 按钮（2238）/ `finishRun`：只把 `M.run` 设成 null。建议回营地时把局内字段清掉，或者在营地隐藏金币余额。

### BUG-009 · S4 · 存档校验没有覆盖 `M.run`：导入异常数据也能通过
- **Severity**：S4 · **Priority**：P3 · **Category**：Save · **Frequency**：Always（需要手改存档或存档码）
- **实际**（`t6_edge.cjs` malformed）：`normalizeSave` 会严格校验其他字段，但下面这些 `run` 都能导入成功：`run:5`、`run:"x"`、`run:{}`、`squad:"zzz"`、`danger:99`。其中 `{danger:99, over:'win', score:1000}` 一导入就结算出 **643 金魂**；`run` 是数字时，`loseHeart` 里的 `M.run.over='lose'` 写不进去，这一局理论上永远不会结束（从代码推断）。`startRun` 也不会把 `danger` 限制在 `dangerMax` 以内（`startRun('std',4)` 在 `dangerMax=1` 时成功，不过 UI 上有限制，正常操作走不到）。
- **代码位置**：`normalizeSave`（586-650）里没有 `run` 字段；`startRun`（2208-2212）。
- **建议**：校验 `run` 是对象，`squad∈SQUADS`、`0≤danger≤DANGER_MAX`、`hearts/score/goals/bosses` 是非负整数、`over∈{null,'win','lose'}`，不合法就丢弃 `run`。

## 3. 设计问题（不算 bug，请设计确认）

1. **营火能把心加到 5 颗**：`HEART_MAX=5`，所以 3 心的队伍（甚至 2 心的赌徒）满心时休息也会 +1，最多到 5。设计写的是"回 1 颗心"，是否允许超过开局上限？
2. **深入金库每层通关不算「达成目标」**，不加分（`settleRoute` 遇到 delve 直接 return），而普通、精英轮达成目标是 +20×章。
3. **新玩家在营地打第一次每日挑战，就能拿到约 14 金魂**（成就奖励，用的是 Lv6 的每日卡组）+ 2 金魂（每日奖励）。实测 0 → 16，比打一整局失败（约 1～6 金魂）多。另外「最远远征」危险 1 倒在第 1 章（4）排在危险 0 通关（3）前面，这是按公式算的结果，请确认是不是想要的效果。

## 4. 测试环境里出现的假象（不是游戏 bug）

- 在 **file://** 下用 `reload()` / 切换语言时，大约 3/16 次新页面读到的是旧的 localStorage（`dbg11.cjs`：file:// 丢失 3/16，**同样的脚本走 HTTP 0/16**；`dbg12.cjs` 的写入追踪证明旧页面确实已经 `setItem` 成功）。这是 Chromium 在 file:// 下跨进程读 localStorage 的时序问题。t2 有两组在"结算页刷新"时的失败、t6 第一次"局内切语言后进度没了"，都是这个原因；改用 HTTP 复测，切换语言后进度、心、地图位置都正常保留。
